# DG5F 보정 가이드 — calibrate_dg5f.py 실행 시 해야 할 동작

보정은 채널별로 "내 손이 실제로 움직이는 각도 범위(min/max)"를 기록하는 과정이다.
**그 채널이 진짜 최대로 움직이는 자세를 한 번씩은 만들어줘야** 로봇 손 매핑이 정확해진다.
빠뜨린 채널은 기본값이 남아 해당 손가락이 덜 굽거나 과하게 굽는다.

> **⚠️ 2026-07-28: 이전 보정값(07-20)은 무효다.** MCP 굽힘 프록시가 `_bend` →
> `_bend_mcp`(굽힘 평면 투영)로 바뀌어 같은 자세에서 rest 값이 3~8° 낮게 나온다.
> 또 07-21에 `thumb_cmc`/`thumb_opp` 프록시가 이미 한 번 바뀌었다. 반드시 재보정할 것.

> **왜 이번 보정이 중요한가 (ratio 모드)**: 현재 매핑은 `ratio` 모드라 **사람 범위가 곧
> 매핑 이득**이다. 사람 폭이 좁게 잡히면 그만큼 로봇이 과하게 움직인다. 실제로 07-20 보정의
> `index_mcp` 폭이 0.40 rad밖에 안 돼 이득이 **4.11배**가 됐고, 손을 펴서 모으기만 해도
> 로봇 검지가 49° 굽는 증상이 나왔다(07-28 실측). `direct` 모드였다면 대부분 안 쓰인다.

```bash
cd vision/dg5f
# mediapipe가 설치된 공용 venv(vision/.vision) 활성화 후 실행할 것 — 레포 루트 README 참고
python calibrate_dg5f.py
# 종료: 웹캠 창에서 q → dg5f_calibration.json 자동 저장
```

## 좌·우 양손을 다 쓸 때 — **반드시 한 세션에서** (2026-07-28)

- **두 번 실행하면 뒤가 앞을 덮는다.** `calibrate_dg5f.py`는 `dg5f_calibration.json`을
  통째로 덮어쓴다(채널별 `human_ranges` 하나뿐, 손 구분 없음). 왼손 보정 후 오른손 보정을
  따로 돌리면 **왼손 보정은 사라진다.** → 한 번 실행해서 왼손 routine → 오른손 routine →
  그다음에 `q`.
- **좌우 공용이 맞다** — 프록시가 손 방향·거울상에 불변이기 때문. 07-28 라이브 4개 런에서
  확인: 같은 동작의 사람 프록시가 좌/우에서 부호·크기 모두 일관
  (`index_abd` −5.4/−6.4/−7.3/−6.8°, `ring_abd` +3.6/+5.0/+5.7/+5.1°).
  굽힘은 부호 없는 각이라 원래 불변이고, `_bend_mcp`의 측면축 제거도 축 **부호**와 무관하다.
  로봇 좌/우 대응은 보정이 아니라 `map_to_dg5f(hand=...)`의 끝단 미러가 담당한다.
- **양손이면 극값 유지 시간을 늘릴 것.** 보정은 백분위 2/98이라 극값이 **세션 전체의 2%
  이상** 관측돼야 잡힌다. 세션이 두 배로 길어지므로, 각 극값을 **손마다 3회 × 2초 이상**
  유지할 것(그래야 3~4%로 여유가 남는다). 세션을 필요 이상 길게 끌면 오히려 짧은 peak가
  잘리니 전체 **2분 40초 내외**로 끝낼 것.

## 촬영 조건 (동작만큼 중요 — 먼저 읽을 것)

| 조건 | 이유 |
|---|---|
| **손목 곧게 고정, 손가락만 움직이기** | 첫 마디(MCP) 굽힘각을 손목 랜드마크 기준으로 계산 — 손목을 꺾으면 손가락 안 굽혀도 굽힌 걸로 오염됨. **가장 흔한 오염원** (평면 투영으로도 이건 안 걸러진다) |
| **손바닥이 카메라 정면** | 단일 카메라라 깊이(z) 부정확 → 손이 옆으로 돌면 각도 왜곡. 실제 텔레옵 때 쓸 방향으로 보정 |
| **극값에서 2초 이상 멈추기** | 백분위 2/98 누적 — 스치듯 지나가면 극값이 통째로 잘린다. 양손 세션이면 특히 중요(위 항목 참조) |
| **천천히, 흔들지 않기** | 모션블러 튐값이 극값을 오염. 망친 것 같으면 q로 끝내고 재실행(덮어쓰기) |
| 손은 화면 중앙, 프레임의 1/2~2/3 크기 | 너무 작으면 랜드마크 정밀도↓, 너무 크면 잘림 |
| 텔레옵에 쓸 손으로 보정 | 좌우 공용이라 한쪽만 해도 되지만, 양손 쓸 거면 위 "양손" 절 참조. **손 좌/우 선택은 GUI ②의 라디오 버튼**에서 한다(옛 `vision_node <hand>` 인자 방식 아님) |

## 보정 동작 체크리스트 (손마다 각 3회, 극값에서 2초 이상 유지)

1. ☐ **펴기 + 뒤로 살짝 젖히기(과신전) ↔ 주먹 꽉 쥐기**
   — 굽힘 채널 전체의 기본 범위. 과신전을 해야 "완전히 편 상태"가 진짜 min으로 잡힘
   (안 하면 로봇 손이 항상 살짝 굽은 채로 시작함)
2. ☐ **손가락 하나씩 개별로 굽혔다 펴기** (검지→중지→약지→새끼→엄지)
   — 채널 분리 + 개별 극값
3. ☐ **갈고리(hook) 자세**: 첫 마디는 편 채 둘째·셋째 마디만 구부리기 (손톱이 손바닥 향하게)
   — PIP 채널의 진짜 최대 분리 (주먹만으로는 안 나옴).
   ※ **DIP(n_4)는 2026-07-21부터 보정 안 씀** — z 추정 부실로 측정 대신 `0.75×PIP`로 유도.
     그래도 PIP를 제대로 잡으려면 이 자세는 여전히 필요(DIP는 PIP 따라감).
4. ☐ **★★ ㄱ자(테이블탑) 자세**: 첫 마디만 **90°까지** 꺾고 둘째·셋째 마디는 쭉 펴기
   — MCP 채널의 진짜 최대. **검지→중지→약지 순으로 하나씩, 확실히 90°까지.**
   ※ **07-20 보정에서 실제로 빠졌던 동작이 이거다.** 당시 결과가
     `index_mcp` max 0.497 / `middle_mcp` 0.580 / `ring_mcp` 0.902 rad로,
     새끼(1.261)만 정상이고 나머지 셋이 한참 모자랐다. 물리캡(1.7)에 걸린 게 아니라
     **그만큼밖에 안 굽힌 것**. 이번엔 이 동작에 시간을 가장 많이 쓸 것.
5. ☐ **엄지 가로 벌림↔모으기(손바닥 평면 안)**: 쫙 벌렸다 ↔ 검지 옆에 붙이기,
   이어서 **엄지 끝으로 새끼손가락 뿌리 터치**
   — 벌리기↔모으기가 엄지 CMC(1_1, thumb_cmc) 채널 — 2026-07-20 프록시 교체
   (`_thumb_abduction`, 1→2 마디의 손바닥 평면 투영각)로 옛 보정값이 무효라 **필수**.
   새끼뿌리 터치는 대향(1_2)의 최대 — "접기"가 아니라 손바닥을 가로지르는 동작
6. ☐ **엄지-검지 OK 사인 (집기)**
   — 엄지 MCP/IP 실사용 범위 (파지 핵심 자세)
7. ☐ **손가락 편 채 쫙 벌리기 ↔ 모으기**
   — 벌림(n_1) 채널. 검지·중지·약지·**새끼(pinky_lat)** 전부 게이트 해제 상태라 **필수**.
   ※ 2026-07-28 정정: 옛 문서의 "pinky_lat만 게이트 유지"는 틀림 — 07-20에 해제됐다.
     현재 게이트(항상 0)인 채널은 `pinky_cmc` **하나뿐**이다.
   ※ 중지(3_1)는 기준 손가락이라 정의상 항상 0 — 보정 폭 0으로 나와도 정상.
8. ☐ **(선택) 손 오므려 컵 모양** ↔ 손 평평하게 펴기
   — 새끼 손바닥접기(5_1, pinky_cmc) 채널.
   ※ 2026-07-28 정정: 이 채널은 **07-20에 다시 게이트됐다**(`gated=True` → 항상 0).
     지금은 보정해도 매핑에 안 쓰인다. 게이트를 풀 계획이 없으면 **건너뛰어도 된다.**
9. ☐ **(선택) 엄지 앞뒤(안테포지션)**: 손바닥 정면 유지한 채 엄지만 카메라 쪽으로 들었다
   ↔ 손바닥 평면으로 되돌리기
   — 엄지 대향(1_2, thumb_opp) 채널.
   ※ 2026-07-28 정정: 이 채널만 프록시 단위가 각도가 아니라 **거리**라서
     보정의 `hmin/hmax`를 **매핑이 읽지 않는다**(`THUMB_OPP_D_OPEN/D_FULL` 상수가 담당).
     보정 품질과 무관하므로 **건너뛰어도 된다.** 대향 깊이가 안 맞으면 그 두 상수를 조정할 것.
10. ☐ **엄지 최대한 쭉 뻗기 (2026-07-15 v3 — 선택, 하면 더 정밀)**: 엄지를 손에서
    최대한 멀리 곧게 뻗은 상태를 **방향 2~3가지**(옆으로/대각선/벌린 채)로 각 **2초 유지**
    — 엄지 손끝 IK의 펴짐 기준 `thumb_straight_ratio`(|엄지끝−CMC| 직선/엄지 마디합의
    p95, "직진도")가 여기서 잡힘. v3부터 같은 프레임 랜드마크끼리의 비라서 카메라
    깊이 오차·손 크기와 무관 — **빠뜨려도 기본값 0.97로 정상 동작**하지만, 본인 엄지의
    실제 직진도로 맞추면 100% 폄 판정이 더 정확해진다.

한 손 약 1분 20초, 양손이면 2분 40초 내외. 순서는 위 번호 순서 추천.
(8·9번을 건너뛰면 한 손 1분 내외)

## 문제 있을 때

- 특정 손가락이 덜/과하게 굽음 → 콘솔의 관측 결과에서 해당 채널 범위 확인, 해당 동작 다시 하고 재보정.
  **과하게 굽으면 그 채널의 사람 폭이 좁게 잡힌 것**(ratio 이득↑)이므로 극값 동작을 더 확실히 할 것.
- 손을 펴서 모았는데 검지가 앞으로 굽음 → `index_mcp` max 확인(1.2 미만이면 동작 4 재실행).
  그래도 남으면 `_bend_mcp`의 평면 투영이 덜 걷어낸 것 — `BEND_MCP_PLANAR=False`로
  A/B 비교한 로그와 함께 개발 담당에게 전달.
- 엄지가 반대로 움직임 → 보정 문제가 아니라 방향 문제 — `dg5f_angles.py`의 해당 채널
  (dg_min, dg_max) 스왑 (개발 담당에게 로그 파일명과 함께 전달).
- 벌림이 한쪽으로만 치우치거나 끝에서 멈춤 → 보정이 아니라 `RATIO_LIMIT`의 좌표계 문제일 수
  있다(2026-07-28 벌림 3채널 사고 참조). `dg5f_angles.py`의 벌림 블록 주석 확인.
- 재보정은 언제든 재실행 (이전 값 덮어씀 — **양손 보정 중이면 한 세션 안에서 끝낼 것**).
