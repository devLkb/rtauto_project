# "파지 직전까지" 계획 — 카메라로 보고 손 자세를 스스로 정하기

작성 2026-09-17. 같은 날 사용자 결정을 반영해 v3까지 개정.

> ⚠️ **설계 제안 문서다.** 관찰·행동 계약의 정본은
> [`RL_POLICY_REDESIGN.md`](RL_POLICY_REDESIGN.md)이고, 이 문서는 그 계약을 **어디까지
> 줄여서 먼저 만들 것인가**를 정한다. 계약 본문을 여기서 바꾸지 않는다.

**목표**: 3D 카메라(D405)로 물체를 보고, **팔이 스스로 목표를 정해** 파지가 잘 되는
직전 자세까지 움직인 뒤 정지한다. 파지는 하지 않는다.

**사람이 적어 넣는 값은 없다.** 물체 목록도, 물체별 좌표도, 파지 자세도 없다.
목표 자세는 카메라가 볼 때마다 **매번 새로 계산된다**(원칙 1).

## 1. 무엇을 배우고 무엇을 계산하는가 — 가장 오해되기 쉬운 부분

일을 둘로 나눈다.

| | 무엇 | 어떻게 |
|---|---|---|
| **① 어디로 갈지** | 카메라로 물체를 보고 "손을 여기에, 이 방향으로, 이만큼 벌려서" | **학습.** 시스템이 매번 스스로 정한다 |
| **② 거기까지 어떻게 가나** | 목표가 정해지면 어깨·팔꿈치·손목을 몇 도로 꺾을지 | **계산.** 답이 하나로 나온다 |

**자율성은 전부 ①에 있다.** ②를 계산에 맡긴다고 해서 "미리 정해진 대로 움직인다"가
되지 않는다 — 목적지가 매번 달라지기 때문이다. 사람이 컵을 잡을 때 "저 컵 오른쪽에서
이 방향으로"는 눈으로 보고 정하지만, 어깨를 몇 도 꺾을지는 의식하지 않는 것과 같다.

### 동작 순서 (2026-09-17 사용자 결정)

```text
보고  →  정하고  →  가고  →  다시 보기  →  (어긋났으면 다시 정하고 또 간다)
```

**가는 도중에 실시간으로 궤적을 고치지는 않는다.** 도착한 뒤 다시 관측해서 어긋났으면
목표를 새로 정해 다시 간다. 재관측은 하되, **그 보정을 팔 학습으로 만들지 않는다.**
이유는 §5.

## 2. "파지까지 안 한다"가 실제로 무엇을 빼는가

[`RL_POLICY_REDESIGN.md`](RL_POLICY_REDESIGN.md) §3이 정책이 배울 행동을 5단계로 정의한다.

| 단계 | 하는 일 | 실제 로봇에서 |
|---|---|---|
| 재관측 | 물체를 화면 안에 두고 더 잘 보이게 팔을 움직임 | **한다** |
| 접근 | 보이는 형상에 맞춰 목표 자세를 정하고 다가감 | **한다 — 여기서 멈춘다** |
| 접촉 형성 | 손 20관절로 지지 접촉 만들기 | 안 한다 |
| 파지 확인·유지 | 살짝 들고 흔들어 보며 유지 | 안 한다 |
| 복구 | 미끄러지거나 놓쳤을 때 되돌리기 | 안 한다 |

**빠지는 3단계는 전부 "손가락이 물체에 닿은 뒤"의 일**이다. 그래서:

- **좋은 소식** — 가장 어렵고 가장 실물과 어긋나기 쉬운 부분을 실제 로봇에서 안 한다.
  손끝 센서가 없다는 제약([`../CLAUDE.md`](../CLAUDE.md) 하드웨어 표)도 문제가 되지 않는다.
- **나쁜 소식** — 남은 2단계가 **정확히 "물체마다 자세가 다르다"는 문제**다.
  파지를 뺐다고 그게 없어지지 않는다. 오히려 **그것만 남는다.**

## 3. 핵심 — 파지를 빼면 채점 방법이 사라진다

"파지 직전 자세"가 좋은 자세인지 **어떻게 아는가?** 답은 하나뿐이다 — **거기서 실제로
잡아 보면 안다.**

이건 추측이 아니라 이미 측정된 사실이다
([`GRASP_POINT_ARCHITECTURE.md`](GRASP_POINT_ARCHITECTURE.md) §2, 게이트 4 실측):

| 측정한 것 | 결과 |
|---|---|
| paper_cup, 기본 배치 | 10번 중 3번만 파지 성립 |
| paper_cup, 물체에 맞춘 배치 | 10번 중 10번 성립 — **학습에 쓰지 않은 물체인데도** |
| 배치 9가지를 바꿔 가며 측정 | 성립률이 10 %에서 95 %까지 벌어짐 |

**손이 어디서 어떤 방향으로 접근하느냐가 성공을 지배한다.** 그리고 이 숫자는
**전부 "끝까지 잡아 봐서" 나온 것**이다.

> 💡 **이 게이트 4 스윕이 곧 우리가 만들어야 할 채점표의 축소판이다.**
> 새 방법을 발명할 필요가 없다 — 이미 하던 것을 넓히면 된다.

### 그래서 채택하는 구조

```text
[가상 세계]  자세 후보를 훑어 가며 끝까지 잡아 본다
                 →  "이 형상 + 이 자세 → 잡혔다/못 잡았다" 채점표
                                          ↓ 이 채점표로 배운다
[예측기]     보이는 모양  →  파지 직전 자세
                                          ↓
[실제 로봇]  그 자세까지 계산으로 팔을 움직이고 정지. 잡지 않는다.
```

**가상 세계에서 파지를 빼면 안 된다. 실제 로봇에서만 뺀다.**

## 4. 걸림돌에 대한 답 — 물체 이름이 아니라 "보이는 모양"으로 정한다

"물체마다 안정적인 자세가 다르다"를 푸는 방법은 세 가지뿐인데, 둘은 이 프로젝트가 이미
금지한 방법이다.

| 방법 | 판정 |
|---|---|
| 물체마다 사람이 자세를 미리 넣어 준다 | ❌ **프로젝트 목적이 금지한다.** 지금 남아 있는 물체별 상수(`place`)도 **고쳐야 할 결함**이다 |
| 물체 이름을 맞히고, 이름마다 정해진 자세를 쓴다 | ❌ 같은 이유. 이름을 모르는 물체에서 곧바로 막힌다 |
| **보이는 모양의 숫자로 자세를 정한다** | ✅ **이것만 남는다** |

계약 문서가 이미 정의해 뒀다([`RL_POLICY_REDESIGN.md`](RL_POLICY_REDESIGN.md) §4-3):

> 파지점은 3D 점 하나가 아니라 **손바닥의 위치·방향, 접근 경로의 마지막 구간, 필요한
> 벌림 폭과 닿아도 되는 영역**의 묶음이다.

즉 "이 물체는 컵이다"가 아니라 **"지금 보이는 표면이 폭 6 cm, 긴 방향은 이쪽, 위쪽에
9 cm 여유가 있다"** 같은 숫자로 자세를 정한다. **물체 이름을 맞히는 기능은 아예 만들지
않아도 된다.**

## 5. 팔 학습을 필수 경로에서 뺀 이유 (2026-09-17 확인·결정)

### 5-1. 확인한 사실 — 팔을 포함한 학습은 **한 번도 돌아간 적이 없다**

| 확인한 것 | 결과 |
|---|---|
| `superdex/results/` 의 학습 결과 **전부** | **2026-09-09 또는 그 이전** |
| 팔 6축 포함 방식(`arm_hand26`) 구현일 | **2026-09-10** |
| → 결론 | 환경은 만들어져 있지만 **구조 확인까지만** 했고, 학습은 **0회** |

이전 판(v2)은 이걸 "돌리면 되는 일"처럼 적었다. **틀렸다.** 팔 포함 학습은 이 프로젝트
최초의 시도가 되며, 가장 큰 미지수다.

### 5-2. 그런데 우리 목표에는 팔 학습이 **필요하지 않다**

팔이 해야 하는 일은 **"정해진 목표 자세로 가서 멈추기"** 하나다(§1의 ②).
목표가 주어지면 관절 각도는 계산으로 나온다. 이미 정확한 답이 있는 것을 배우게 할 이유가 없다.

**팔 학습이 값어치를 갖는 경우는 하나뿐이다** — 가는 도중에도 계속 보면서 실시간으로
궤적을 고치는 것. 그런데 **사용자가 "보고 → 정하고 → 가고 → 다시 보기"를 선택했다**
(2026-09-17). 이 방식에는 실시간 보정이 필요 없다.

### 5-3. 팔 학습(act26)은 어떻게 하나

**버리지 않는다. 필수 경로에서만 뺀다.** 나중에 "가면서 고치기"가 꼭 필요하다고
판단되면 그때 별도 항목으로 올린다. 구현된 `arm_hand26` 환경은 그대로 둔다.

### 5-4. 그래서 손 관절 20개는 그대로 간다

26축을 한꺼번에 학습하는 부담이 사라졌으므로 손을 줄일 이유가 없다.
**이미 학습된 손 정책 `dg5f_grasp_v8.onnx` 가 손 20개 + 손목 고정 구성**이고, 그걸 그대로
쓴다. 줄이지도, 새로 배우지도 않는다.

> 참고로 손을 "쥐고 펴기"로 줄이는 것은 **Unity를 버린 이유와 같은 종류의 실수**다.
> Unity를 버린 이유는 보상을 손봐도 못 메우는 **표현력** 문제였다. 손을 줄이면
> 공·상자·원통마다 달라야 하는 엄지 방향과 손가락 벌림을 **표현할 수단 자체가 없어진다.**
> 우리 걸림돌이 바로 "물체마다 자세가 다르다"인데, 표현 수단을 없애고 그 문제를 풀 수 없다.
> 나중에 성공한 파지들의 손 모양을 모아 재 보고, 근거를 갖고 줄이는 것은 가능하다.

## 6. 주고받는 값 (D-1에서 확정할 것)

무엇이 안쪽에 들어가든 **주고받는 값은 하나로 고정**한다. 그래야 계산 방식과 학습 방식을
같은 자리에 꽂았다 뺐다 할 수 있다.

| 묶음 | 내용 | 비고 |
|---|---|---|
| 언제·어디 기준 | 촬영 시각, 내보낸 시각, 기준 좌표계(로봇 베이스) | 촬영 시각과 현재 시각을 섞지 않기 위함 |
| **누가 만들었나** | `계산 방식` / `학습한 예측기` | 두 방식을 비교하려면 필수 |
| 손바닥 | 위치 3개(m), 방향 4개(쿼터니언), 접근 방향 3개, 남은 거리 1개(m) | 축 순서·단위를 문서에 못 박는다 |
| **손 모양** | **관절 목표각 20개(rad) + 유효 표시 20개** | 관절 순서의 정본은 **로봇 URDF 하나**(`dof_names`가 거기서 나온다). 다른 파일에 다시 타이핑하지 않는다 |
| 참고값 | 벌림 폭 1개(m) | **사람이 읽기 위한 값. 제어에 쓰지 않는다** — 쓰면 정본이 둘이 된다 |
| 판정 | 신뢰도 1개 + **`받아들임 / 거절`**, 거절이면 이유 | 범위 밖 · 깊이 나쁨 · 팔이 못 닿음 · 확신 없음 |

핵심 두 가지:

- **"거절"이 곁다리가 아니라 정식 결과다.** 모르면 멈추는 것이 합격 기준 중 하나다(§8).
- **정본은 한 곳.** 관절 순서는 URDF, 설정값은 `config/rtauto_config.py`.
  숫자를 두 번째 파일에 다시 적지 않는다(원칙 1).

지금 이 경로에 Unity는 끼어 있지 않다(카메라 → 파이썬 → 관절각 계산 → RTDE → 팔).
**C# 쪽은 만들지 않는다.** 필요해지면 그때 만든다.

## 7. 단계별 계획

### 7-1. 카메라가 없어도 지금 할 수 있는 것

| # | 할 일 | 끝났다고 볼 조건 |
|---|---|---|
| D-1 | **주고받는 값 확정** (§6) | 두 방식이 같은 자료구조를 채우고, 가짜 값으로 팔까지 움직여 본다 |
| D-2 | **채점표 만들기** — 자세 후보를 훑어 가며 실제로 잡아 보고 성공·실패 기록. **기존 오라클 스윕 도구를 넓히는 것**(`gate4_object_sweep.py`, `object_oracle_sweep.py`) | 형상 여러 종 × 자세 여러 개의 성공·실패 표가 파일로 남는다 |
| D-3 | **점 덩어리 합성 실측** — **이 길의 최대 미검증 항목** | 표면 메시 + 시야 자르기 + 가림 판정으로 "카메라가 볼 법한 점"이 나오는 것을 확인 |
| D-4 | **예측기 학습** — D-3 점 덩어리 → D-2 채점표의 좋은 자세 | 학습에 안 쓴 형상에서도 좋은 자세를 내놓는 것이 숫자로 확인된다 |
| D-5 | **자세 → 관절각 계산 → 가짜 팔(URSim) 이동** — `arm/run_ursim.ps1` | 계산된 자세로 가짜 팔이 이동해 정지. 못 닿는 자세는 움직이기 전에 거절 |
| D-6 | **손목 카메라 장착값 설정 자리 뚫기**(원칙 1) | `config/rtauto_config.py`에 키가 생기고 0값으로도 경로가 돈다 |

**순서**: D-1 → D-5(배관 먼저) → D-2(채점표, 오래 걸리므로 백그라운드) → D-3 → D-4.
D-5를 앞에 두는 이유는 배관이 뚫려야 D-4 결과를 꽂아 볼 자리가 생기기 때문이다.

### 7-2. 카메라·스위치가 와야만 되는 것

| # | 할 일 | 왜 대기인가 |
|---|---|---|
| Q1 | D405 영상·깊이 취득, 실제 장착 시야 확인 | 물건이 없다 |
| Q2 | **손목 카메라 위치 맞추기(hand-eye)** | 실물 팔을 움직여 재야 한다. ⚠️ **한 번도 해 본 적 없는 작업** |
| Q3 | 측정한 위치가 실제 기준점과 맞는지 대조, 허용 오차 정하기 | 위와 같음 |
| Q4 | 실물 팔로 접근 후 정지, 사람이 실제로 잡을 수 있는지 반복 확인 | 스위치·랜 어댑터도 필요 |

점 덩어리가 아무리 정확해도 팔이 엉뚱한 곳으로 간다.

## 8. 합격 기준 (반복 시험 **전에** 정한다)

파지를 하지 않으므로 "잡았다"로 채점할 수 없다. 대신 넷으로 나눈다.

| 무엇을 재나 | 어떻게 재나 |
|---|---|
| 계산 방식보다 나은가 | 같은 형상·같은 조건으로 두 방식을 돌려 파지 성립률 비교 (계약 R3) |
| 학습에 안 쓴 물체로 넘어가는가 | 학습에 쓰지 않은 형상에서 성립률을 따로 낸다 |
| 실제 로봇에서 위치가 맞았나 | 계산한 자세와 실제 도달 자세의 차이. 허용치는 Q3 실측 후 확정 |
| **모를 때 멈추나** | 벌림 폭 밖 물체·깊이가 나쁜 장면을 일부러 준다. **거절해야 통과** |

마지막 항목이 특히 중요하다. **"모르면 멈춘다"가 동작하는 것이
"항상 성공한다"고 주장하는 것보다 안전하고 설득력 있다.**
