# `docs/docs2/` — 사람에게 설명하려고 쓴 글 (한국어 서술형)

계약서가 아니라 **설명하려고 쓴 문서**들이다. 정확한 값·계약이 필요하면 여기가 아니라
[`docs/modules/`](../modules/README.md)와 코드를 본다.

> **2026-09-16 정리.** 구세대(UR5e + 왼손, Unity 파지 학습) 기준으로 쓰인 3개
> (`GRASP_LIFT_발표자료.md`, `GRASP_LIFT_설명.md`, `기술선택_설명.md`)를
> [`../archives/`](../archives/README.md)로 옮겼다. 지금 읽으면 현행 구성으로 오해하기 때문이다.
> 남은 3개는 **실물 손(DG-5F)** 관련이라 지금도 쓸모가 있다.

## 특히 중요한 것 하나

[`TESOLLO_SDK_기술부채_조사.md`](TESOLLO_SDK_기술부채_조사.md)는 **지금도 실무에 직접 영향을
주는 결론**을 담고 있다.

> DG-5F 는 **연결 방식과 무관하게 전체에서 TCP 연결을 하나만 받는다**(2026-08-31 실물 실측).
> DGManager 를 켜 둔 채로는 개발자모드 SDK 경로도, 사용자모드 Modbus 경로도 붙지 않는다.

그래서 실물을 쓰려면 **SDK 브리지를 유일한 연결로 쓰거나**, DGManager 연결을 끊고
자세를 읽어 오는 브리지를 쓰거나 둘 중 하나를 택해야 한다 →
[`docs/modules/REAL_BRIDGES.md`](../modules/REAL_BRIDGES.md) §2.

## 읽을 때의 규칙

- **설명글과 값의 정본은 다르다.** 숫자가 코드와 다르면 **코드가 맞다.**
- `ONNX_인계_설명.md`는 **Unity 파지 학습 시절**(2026-07-29)에 쓰였다. 넘겨주는 방식의
  설명으로는 유효하지만, 지금 파지 학습은 SuperDex 가 맡는다 →
  [`SUPERDEX_POC_PLAN.md`](../SUPERDEX_POC_PLAN.md).
