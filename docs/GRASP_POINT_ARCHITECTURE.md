# 파지점 자율 결정 — 아키텍처 조사와 권고

작성 2026-09-10. **결정 문서가 아니라 근거 문서다** — 최종 채택은 사용자 승인 사항이다.

2026-09-10 프로젝트 최종 목적이 **"처음 보는 물체도 스스로 파지점을 찾아 파지"** 로
바뀌면서(로드맵 v17), "파지점을 무엇으로부터 정하는가"가 최대 기술 격차가 됐다.
이 문서는 그 질문을 **리포 내부 사실 + 실측 + 외부 문헌**으로 조사한 결과다.

관찰·행동 계약의 정본은 [`RL_POLICY_REDESIGN.md`](RL_POLICY_REDESIGN.md)이고, 이 문서는
그 계약의 **개정 근거를 제안**한다. 계약 자체를 여기서 바꾸지 않는다.

---

## 0. 요약 — 세 줄

1. **선택지를 새로 만들 필요가 없었다.** 계약 문서 §2·§4 가 이미 아키텍처를 확정해
   뒀다 — "인식·후보 생성기가 후보 M=8 개를 내고, RL 정책이 **선택**하고 실행한다".
2. **그런데 그 설계는 다지 손에 대한 현재 통설과 다르다.** 최근 연구(CoRL 2025
   ClutterDexGrasp)는 다지 파지에서 **teacher-student**(시뮬 특권 상태로 teacher 학습 →
   부분 점군 student 로 증류)로 수렴했다. 후보 슬롯 방식은 2지 그리퍼 계열의 형태다.
3. **teacher-student 를 권고한다. 이미 만든 것이 그대로 teacher 단계이기 때문이다** —
   현행 게이트 2 환경은 GT 물체 자세를 관찰로 주는데, 이는 계약이 "유출"로 금지한
   구성이지만 teacher-student 패러다임에서는 **의도된 1단계**다.

## 1. 내부 근거 — 계약 문서는 이미 답을 갖고 있었다

[`RL_POLICY_REDESIGN.md`](RL_POLICY_REDESIGN.md) (v5, 2026-09-07) 는 **설계만 하고 구현하지
않은** 문서다("이번 개정의 산출물은 이 문서 하나다. … 코드·설정·모델 변경은 수행하지
않는다"). 거기 이미 적혀 있는 것:

**§2 시스템 역할과 정보 경계** — 모듈 분리가 명시돼 있다:

| 구성요소 | 책임 |
|---|---|
| 인식·후보 생성기 | 타깃 추적, 관측 형상 복원, **복수 후보와 불확실성 제공** |
| RL 정책 | 관측 이력에 따라 **후보와 팔·손 움직임 선택** |

**§4-3 "파지점을 찾는다"의 구체적 의미** — 후보의 정의와 개수까지:

> 파지점은 3D 점 하나가 아니라 **팜의 위치·방향, 접근 경로의 마지막 구간, 필요한 개구폭과
> 허용 접촉 영역**의 묶음이다. … 초기 최대 후보 수는 **M=8** 로 제안한다.

**§5-1 관찰 v3** — 점군을 정책에 직접 넣지 않는다고 **명시적으로 배제**한다:

> 카메라 영상·전체 점군을 이 벡터에 직접 넣지 않는다. 인식·후보 생성기가 관측 표면을
> 처리하고, 정책에는 타깃의 위치·관측 범위·품질, **파지 자세 후보 8개**, 주변 여유거리와
> 손끝별 표면 정보를 넣는다.

→ 즉 계약은 **"후보 생성기 + 선택 정책"** 을 채택하고 **"end-to-end 점군 RL"** 을 배제했다.

### 1-1. 현행 환경은 이 계약의 의도적 축소판이다

로드맵 v15: "관찰 v3(366)·행동 v3(팔6+손20) 계약은 엔진 독립 자산으로 유지하며,
**게이트 2에서 손 20관절·손목 고정으로 축약해 재사용한다**".

| | 계약 (`obs_v3_366` / `act26`) | 현행 게이트 2 환경 (`obs65` / `act20`) |
|---|---|---|
| 파지 후보 8슬롯 | 있음 | **없음** — `place` 상수가 대신 |
| 손목 카메라 관측(위치·범위·품질) | 있음 | **없음** — GT 물체 자세를 직접 줌 |
| 손끝별 표면 정보 | 있음 | 없음 (접촉력·거리만) |
| 팔 6축 액션 | 있음 | **없음** — 손목 용접 |
| 재관측·후보 변경 행동 | 있음 | 없음 |

**축소는 문서화된 의도**였고 게이트 0~4(엔진 선택)에 필요한 최소 구성이었다.

## 2. 실측 근거 — 게이트 4 가 격차의 위치를 특정했다

| 실측 | 값 | 의미 |
|---|---|---|
| paper_cup, duck_lamp 기본 배치 | 파지성립 **30 %** | 배치가 틀리면 못 잡는다 |
| paper_cup, 물체에 맞춘 배치 | 파지성립 **100 %**(홀드아웃 시드) | 배치만 맞으면 **학습에 쓰지 않은 물체도 잡는다** |
| 배치 9종 스윕 | 성립률 10 %~95 % | 배치가 성공을 **지배**한다 |

**격차는 "잡는 능력"이 아니라 "어디를 어떻게 잡을지 정하는 것"에 정확히 있다.**
이는 계약이 후보 생성기를 별도 모듈로 둔 판단을 실측으로 지지한다.

## 3. 실측 근거 — SuperDex 의 인지 관련 능력

계약 §2 는 "배포 전에는 **시뮬 카메라 영상 → 실제 인식 알고리즘 → 동일 인터페이스**로
검증한다"고 요구한다. SuperDex 에서 그게 되는지 직접 확인했다(2026-09-10).

| 확인 항목 | 결과 |
|---|---|
| 물리 엔진의 카메라·깊이 센서 API | **없다.** `superdex.physics` 에 camera/depth/image 심볼이 없다 |
| 뷰어(polyscope 백엔드) | **RGB 만** — `render()` / `take_screenshot()`, 깊이 버퍼 없음 |
| 깊이 렌더링 경로 | **UnrealCV 백엔드에만 있다**(`unrealcv_client.py`: `"depth": Depth buffer`) — **별도 Unreal 앱**이 필요한 무거운 의존 |
| **표면 기하 쿼리** | **있다.** `get_surface_mesh()` → `coordinates` / `connectivity`, 그리고 `get_sdf_distances()`, `get_points_distance_to_surface()` |

**실측**: 파지 씬의 actor **31개 전부**가 표면 메시를 노출하고, **총 22,808 노드**다
(팜 4,960 / 손가락 근위 지골 각 860~1,210 / …).

### 3-1. 결론 — 깊이 렌더러 없이 점군을 합성할 수 있다

부분 점군(student 단계의 관찰)은 **깊이 렌더러 없이** 만들 수 있다:

1. actor 별 표면 메시 노드(로컬) + actor 변환 → world 점
2. 카메라 시야·법선 방향으로 컬링 → 보이는 면만 남김
3. 가림은 SDF/거리 쿼리로 판정

즉 **UnrealCV 를 들이지 않아도 되고**, 계약이 요구하는 "부분 관측"의 성격(가림·시야 제한)을
그대로 재현할 수 있다.

> ⚠️ **주의 — actor 를 잘못 고르면 실패한다.** 거리 쿼리를 프리팹 집합 actor 에 걸면
> `Actor has no collider` 로 거부된다. 게이트 3 의 접촉 쿼리와 **같은 함정**이다
> (링크 actor 마다 걸어야 한다).
>
> ⚠️ **"시뮬 카메라 영상 → 실제 인식기" 검증은 SuperDex 로 못 한다.** RGB-D 가 필요한
> 이 검증은 **Unity 쪽 역할**이다 — Unity 는 깊이 렌더링이 되고 이미 트윈·시각화 계층으로
> 유지되고 있다. 역할 분담이 기존 아키텍처와 어긋나지 않는다.

## 4. 외부 근거 — 다지 손에서는 통설이 다르다

| 출처 | 무엇을 보여주는가 |
|---|---|
| [ClutterDexGrasp (CoRL 2025)](https://arxiv.org/abs/2506.14317) | **2단계 teacher-student.** teacher 를 시뮬에서 특권 상태 + 혼잡도 커리큘럼으로 학습하고, **부분 점군에서 동작하는 student(3D diffusion policy)** 로 증류. **제로샷 sim2real**, 실물 시연 데이터 0. 혼잡 환경 다지 파지 성공률 **75.1 %** |
| [DexPoint](https://arxiv.org/pdf/2211.09423) | 점군 RL 로 다지 sim2real 일반화 — end-to-end 계열이 성립함을 보인 선행 사례 |
| [point cloud serialization attention (2025)](https://www.sciencedirect.com/science/article/abs/pii/S0031320325007599) | GraspNet-1Billion SOTA, **미학습 물체 87.88 %** — 단 **2지 그리퍼(Franka)** 다 |
| [Economic Framework for 6-DoF Grasp Detection](https://arxiv.org/pdf/2407.08366), [Rethinking 6-DoF Grasp Detection](https://arxiv.org/pdf/2403.15054) | 후보 생성·정제 프레임워크 계열의 성숙도 |
| [End-to-End Dexterous Grasp Learning from Single-View Point Clouds](https://arxiv.org/html/2603.15410) | 부분 관측에서 관통이 적은 파지 생성 |

**핵심 대비:**

- **2지 그리퍼**: "후보 생성기 + 선택" 이 성숙했다(미학습 물체 87.88 %). 6-DoF 자세 +
  개구폭이면 파지가 거의 결정되기 때문이다.
- **다지 손**: 검색 결과가 명시하듯 *"많은 방법이 **다지 손**을 포함한 복잡한 기하를 함께
  다루는 데 여전히 제한적"* 이다. 후보 하나로 20관절 파지를 규정할 수 없다. 최근 성과는
  **teacher-student** 로 나왔다.

## 5. 권고 — teacher-student. 이미 만든 것이 teacher 다

### 5-1. 왜

**현행 게이트 2 환경은 이미 teacher 구성이다.** 관찰 65차원에 GT 물체 자세
(`(bt - center) * 10`)와 GT 기반 지문 거리를 넣고 있다. 계약 §2 는 이를 "GT 유출"로
금지하지만, 그 금지는 **배포 정책**을 향한 것이다. teacher-student 에서는 **teacher 가
특권 상태를 쓰는 것이 정상이고 의도**다.

즉 이 권고는 **지금까지 만든 것을 버리지 않는다**:

| 자산 | teacher-student 에서의 위치 |
|---|---|
| `Dg5fGraspEnv` (obs65/act20, GT 관찰) | **teacher 환경** — 그대로 쓴다 |
| 학습된 `dg5f_grasp_v8` | **teacher 정책의 출발점** |
| 게이트 1 ONNX 계약 | student 배포 경로로 그대로 유효 |
| 게이트 3 팔+손 결합 bot | 팔 6축 확장 시 teacher 환경에 투입 |
| 게이트 4 DR·물체 스윕 도구 | teacher 의 일반화 측정에 그대로 |

### 5-2. 단계

```text
1단계 teacher   특권 상태(GT) + 팔6+손20 + 물체 다양성 + DR 로 RL 학습
                  ↑ 현행 환경의 확장. place 상수는 여기서 제거하고
                    물체를 무작위 배치해 teacher 가 스스로 접근하게 한다
2단계 점군 합성  표면 메시 + 카메라 컬링 + SDF 가림 판정 (§3-1, 렌더러 불필요)
3단계 student   teacher 를 부분 점군 입력 정책으로 증류
4단계 검증      Unity 로 시뮬 카메라 → 실제 인식 경로 확인 (계약 §2 요구)
```

### 5-3. 계약 문서에 제안하는 개정

[`RL_POLICY_REDESIGN.md`](RL_POLICY_REDESIGN.md) 는 v5 이후 **구현되지 않았고**, 그 사이
게이트 0~4 의 실측과 위 외부 근거가 쌓였다. 아래를 개정 후보로 제안한다 — **승인 전에는
계약을 바꾸지 않는다.**

| 계약 현행 | 제안 | 근거 |
|---|---|---|
| 후보 M=8 슬롯을 관찰에 넣음 | **teacher 단계에서는 불필요.** student 단계에서 후보를 쓸지 재검토 | 다지 손에서 후보 하나가 20관절 파지를 규정하지 못한다(§4) |
| "카메라 영상·전체 점군을 벡터에 직접 넣지 않는다" | student 는 **점군을 직접 받는** 구성이 통설 | ClutterDexGrasp / DexPoint(§4) |
| "GT 유출 금지" | **배포(student) 정책에만 적용**으로 한정. teacher 는 특권 상태 사용이 정상 | teacher-student 의 정의 |

## 6. 이 권고의 약점 — 숨기지 않는다

| 약점 | 내용 |
|---|---|
| **증류 단계를 만들어 본 적이 없다** | teacher-student 는 우리가 아직 구현하지 않은 파이프라인이다. 1단계는 기존 자산으로 되지만 2~4단계는 새로 만든다 |
| **throughput 이 정면 리스크가 된다** | ClutterDexGrasp 급 연구는 대규모 병렬 시뮬을 쓴다. 우리 실효값은 **≈470 steps/s** 이고 Ray 병렬 워커가 불안정하다. 물체 다양성 + 팔 6축(26 DOF) + DR 이 겹치면 여기서 막힌다 — **게이트 4 리스크 표의 우선순위가 올라간 이유** |
| **75.1 % 는 우리 목표가 아니다** | 인용 수치는 혼잡 환경 기준이고 하드웨어·물체군이 다르다. **우리 성공 기준으로 환산되지 않는다** — 목표치로 옮겨 적지 마라 |
| **점군 합성은 아직 실측 전이다** | 표면 메시가 나온다는 것(22,808 노드)까지만 확인했다. 컬링·가림 판정을 실제로 구현해 "실제 카메라와 닮은 부분 관측"이 나오는지는 **검증 안 됐다** |
| **계약 문서와 충돌한다** | §5-1 이 점군 직접 입력을 명시적으로 배제한다. 개정 없이 진행하면 문서 간 불일치가 생긴다 |
