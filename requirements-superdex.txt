# ⚠️ torch는 여기에 넣지 않는다 — **머신마다 빌드가 다르기 때문이다.** ray[rllib]은
#    torch를 끌어오지 않고, PyPI 기본 wheel은 Windows에서 CPU 전용이다. 그래서 이
#    파일이 아니라 아래 표대로 **먼저 따로** 설치한다(원칙 1 — 머신마다 다른 값은
#    코드/공용 파일에 박지 않는다).
#
#      머신                    | GPU                      | 설치 명령
#      ------------------------|--------------------------|------------------------------
#      회사 (Windows)          | RTX 2080 8 GB (Turing)   | pip install torch --index-url https://download.pytorch.org/whl/cu124
#      집 (Windows)            | RTX 4070 Ti 12 GB (Ada)  | pip install torch --index-url https://download.pytorch.org/whl/cu124
#      개인 노트북 (Ubuntu)    | Intel Arc 내장 — CUDA X  | pip install torch --index-url https://download.pytorch.org/whl/cpu
#
#    설치 후 확인: `python -c "import torch; print(torch.__version__, torch.cuda.is_available())"`
#      - CUDA 머신은 True 여야 한다. False면 learner를 GPU로 못 쓴다.
#      - **개인 노트북은 False가 정상이다** (CUDA GPU가 없다). CPU learner로도 게이트는
#        진행되지만 느리므로 성능 판정 기준으로 쓰지 않는다.
#    실측 (2026-09-10): 회사 `torch 2.6.0+cu124`, 개인 노트북 `torch 2.14.0+cpu`.
#
#    ⚠️ **CUDA 없는 머신은 `RTAUTO_SUPERDEX_GPUS_PER_LEARNER=0`을 .env에 넣어야 한다.**
#       코드 기본값이 1이라 그대로 두면 Ray가 GPU를 못 잡는다 — docs/SUPERDEX_POC_PLAN.md §8.

# ONNX 내보내기·검증 (게이트 1의 3자 파리티 테스트).
# RLlib 새 API 스택은 ONNX export를 지원하지 않아(ray#45526) torch.onnx.export로
# 래퍼 nn.Module을 직접 내보낸다 — docs/SUPERDEX_POC_PLAN.md §5 게이트 1.
# 핀 확정 2026-09-10 — 게이트 1의 3자 파리티(최대 오차 7.18e-07)가 이 버전 조합의 것이다.
onnx==1.22.0
onnxruntime==1.29.0

# 핀 이력 — 위 세 줄(ray / onnx / onnxruntime)은 원래 핀이 없었다. 게이트 0~4 를 돌린
# 회사 머신(Windows/CUDA)의 `pip freeze` 실측(docs/SUPERDEX_POC_PLAN.md §9 R3)과
# 2026-09-10 개인 노트북(Ubuntu 24.04/CPU)의 새 설치가 **독립적으로 같은 버전으로
# 해석돼** 그 값으로 고정했다. 핀 없이 최신을 따라가면 재현이 깨진다(§9 R3).
