## 세션 1 — 잡은 뒤 물체가 얼마나 돌아가는지 재기 (기울기)

### 사용자 질문
"들어올렸을때 기울기도 0도에 가까웠으면 좋겠는데 이것도 고려해서 지금 파지 테스트중인가"

### 확인한 것 — **아니었다**

채점표의 성공 판정은 두 가지뿐이었다(`superdex/envs/dg5f_grasp_env.py:941`):

1. 손끝이 3개 이상 닿아 있다
2. 중력을 켰을 때 물체가 손 중심에서 6 cm 안에 있다

**물체가 얼마나 돌아갔는지는 재지도, 판정에 넣지도 않았다.** 손 안에서 90도 뒤집혀도
"성공" 으로 기록됐다.

### 한 것

이미 있던 **미끄러짐(slip)** — 파지 성립 시점 대비 손바닥 좌표계 변위 — 의 **회전판**을
같은 자리에 붙였다.

- 기준은 "처음 놓은 방향" 이 아니라 **파지가 성립한 순간의 방향**이다. 일부러 눕혀 놓고
  훑는 자세(tilt+90)를 기울어짐으로 오판하지 않으려는 것.
- ⚠️ **성공 판정에는 아직 안 넣는다 — 기록만 한다.** 몇 도를 넘으면 실패로 볼지는 실제
  분포를 보고 정한다(짐작한 숫자를 먼저 박지 않는다).

| 파일 | 무엇 |
|---|---|
| `superdex/envs/dg5f_grasp_env.py` | `_object_quat_in_palm()`, `_quat_angle_deg()`, `_tilt_ref`, `info["tilt_deg"]` |
| `superdex/scripts/gate2_oracle_search.py` | `run_trajectory` 가 `tilt_end` / `tilt_max` 를 돌려준다 |
| `superdex/scripts/pose_score_sweep.py` | 각 칸에 `tilt_median_deg` / `tilt_max_deg`, `report()` 에 분포 요약 |

### 실측 — 바로 값어치가 나왔다

block_red 4칸, 전부 **성공률 100%** 인데 기울기가 갈렸다:

| 자세 | 잡은 뒤 돌아간 각도 |
|---|---|
| 앞 0.04 m, tilt+45 | **1.8도** |
| 앞 0.04 m, yaw+0 | 4.2도 |
| 앞 0.05 m, tilt+90 | 18.4도 |
| 앞 0.05 m, yaw+0 | **19.2도** |

기존 표는 이 넷을 똑같이 "성공" 으로 적고 있었다.

## 세션 2 — 손끝 센서 없이 "잡았다" 알아내기 (설계 + 코드)

### 사용자 요청
붙여넣은 설계 프롬프트 — 전류 + 위치 오차 + 속도로 접촉을 추정하고, 들어올려 확인하는
구조를 Python 으로 설계.

### SDK 에서 **확인한** 사실 (추측 아님)

`vision/dg5f/vendor/dgsdk-python/libs/DGDataTypes.h` 의 `ReceivedGripperData` 주석:

- `joint` = 도, `current` = **mA**, `velocity` = **rpm**, `temperature` = °C
- 즉 **세 신호가 전부 실제로 들어온다**

⚠️ **다만 지금 브리지는 속도를 안 받고 있다.** `dg5f_sdk_bridge_dgsdk.py` 의
`RECEIVED_DATA_TYPE = [1, 2, 7, ...]` 에 VELOCITY(4)가 없다 → 0 만 들어온다.

또한 `SetCurrentControlMode` / `SetTargetCurrent*` / `SetGraspData(graspForce)` 가 있어
**전류 상한을 걸고 쥐는 것**도 가능하다 — 실측 후 비교할 것.

### 만든 것

| 파일 | 하는 일 |
|---|---|
| `docs/GRASP_CONTACT_DETECTION.md` | **설계 정본** |
| `hand/grasp_contact.py` | 판단 규칙만. 하드웨어가 안 들어온다 |
| `hand/measure_baseline.py` | 무부하 전류 기준표 만들기 (`--fake` 지원) |
| `hand/grasp_sequence.py` | 순서도 (닫기 → 쥐기 → 들기 → 확인) |
| `hand/tests/test_grasp_contact.py` | **손 없이 도는 시험 17개 — 전부 통과** |
| `config/rtauto_config.py` + `.env.example` | 기준값 17개 (원칙 1) |

### 설계에서 중요한 판단 3가지

**1. "멈췄다" 만으로는 절대 안 된다.**
시킨 각도까지 **다 가서** 멈춘 관절도 속도 0, 전류 낮음이다. 이걸 접촉으로 세면 **빈손도
"잡았다" 가 된다.** 그래서 "시킨 데까지 못 갔다"(각도 오차)는 뺄 수 없는 조건이다.

**2. 전류 기준을 숫자 하나로 못 박지 않는다.**
무부하 전류는 관절마다·각도마다 다르다. `measure_baseline.py` 로 관절 20개 × 각도 10도
구간마다 평균·흔들림을 재고, 기준 = `평균 + max(흔들림×6, 80 mA)` 로 쓴다.
**기준표가 없으면 코드가 시작을 거부한다.**

**3. 확인 방법을 바꿨다 — 시험이 설계 구멍을 찾아냈다.**
처음엔 "물체가 빠지면 손가락이 더 닫힌다" 로 잡으려 했다. 그런데 닿은 관절의 목표를 그
자리에 세워 두므로 **물체가 빠져도 손가락이 0.5도밖에 안 움직인다** — 못 잡는다.
→ **집어보기**로 바꿨다: 들어올린 뒤 일부러 5도 더 조여 보고, 실제로 들어가면 빈손.
확인이 끝나면 되돌린다.

### 정직하게 — 아직 모르는 것

- 무부하 전류가 실제로 얼마인지 모른다. 잠정값이 한 자릿수 틀릴 수도 있다
- 속도(rpm)가 실제로 들어오는지 확인 못 했다 (켜야 한다는 것까지만 확인)
- 집어보기 5도가 종이컵을 찌그러뜨릴지 모른다
- `SetGraspData` 내장 파지를 안 써 봤다

**실물 검증 0회.** 스위치·랜 어댑터 도착이 선행 조건.
